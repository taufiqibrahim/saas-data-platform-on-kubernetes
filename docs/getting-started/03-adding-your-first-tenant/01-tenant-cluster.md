## Creating Tenant Cluster

We have prepared a shell script to automate the Kind cluster creation.
In real production deployment, the tenant cluster already prepared by using cloud-managed Kubernetes cluster through automation, 
or tenant already have a self-managed cluster. So this Kind cluster only used on our local stack. 

### What the Script Does

The `create-tenant-cluster.sh` script performs the following steps:

1. **Validates prerequisites** - Checks that the root CA certificate exists at the specified path
2. **Creates a Kind cluster** with the following configuration:
   - One control-plane node
   - One worker node labeled with `NodeGroupType: default`
   - IPv4 networking with the default CNI
3. **Configures trusted registry** - Sets up `zot.saas.internal` as a trusted container registry for each node
4. **Installs CA certificates** - Copies the root CA from StepCA into each Kind node and updates the CA trust store
5. **Restarts containerd** - Ensures the new certificates and registry configuration take effect

### Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `ROOT_CA_PATH` | `./docker/step-ca/certs/root_ca.crt` | Path to the root CA certificate file |
| `REGISTRY_HOST` | `zot.saas.internal` | Hostname of the trusted container registry |

Usage

```bash
./deployments/tenants/create-tenant-cluster.sh <CLUSTER_NAME>
```

Example

```bash
# Using default settings
./deployments/tenants/create-tenant-cluster.sh tenant-0

# Or with custom ROOT_CA_PATH
ROOT_CA_PATH=/path/to/your/ca.crt ./deployments/tenants/create-tenant-cluster.sh tenant-0
```

Feel free to experiment with your own Kind configuration by referring to [https://kind.sigs.k8s.io/docs/user/configuration/](https://kind.sigs.k8s.io/docs/user/configuration/).
The configuration is located in-line on `deployments/tenants/create-tenant-cluster.sh`

## Interact With The Cluster

After creating a cluster, we can use `kubectl` to interact with it by using the configuration file generated by kind.

To see all the clusters we have created, we can use the `get clusters` command.

```bash
kind get clusters
saas
tenant-0
```

In order to interact with a specific cluster, we need to specify the cluster name as a context in `kubectl` as the current context:
```bash
kubectl config use-context kind-tenant-0
```

Now we're ready to use the cluster.

## Bootstrap The Cluster

To make it easy, we use a Shell script that automate following:
- Install necessary components such as Cert Manager, External Secret, External DNS
- Create SecretStore

Feel free to check that in `deployments/tenants/bootstrap-tenant-cluster.sh` and adjust as needed.

Feel free to experiment with our own configuration by refering to [https://kind.sigs.k8s.io/docs/user/configuration/](https://kind.sigs.k8s.io/docs/user/configuration/).

Now let's create the `tenant-0` cluster:
```bash
export DOCKER_HOST_IP=<your-host-ip>     # For external-dns etcd connection
export ROOT_CA_PATH=./docker/step-ca/certs/root_ca.crt
export TENANT_ID=tenant-0
export TENANT_KEYVAULT_TOKEN=<tenant-token>

./deployments/tenants/bootstrap.sh
```

## Troubleshootings

### Error ErrImagePull, ImagePullBackOff

Check the error message in Kubernetes pod status:
```bash
...
status:
  conditions:
    ...
    started: false
    state:
      waiting:
        message: 'Back-off pulling image "nicolaka/netshoot:latest": ErrImagePull:
          failed to pull and unpack image "docker.io/nicolaka/netshoot:latest": failed
          to copy: read tcp 172.18.0.3:33362->104.16.101.215:443: read: connection
          reset by peer'
        reason: ImagePullBackOff
```

Solution:

Pre-pull the image on the host and load it into KIND:
```bash
docker pull nicolaka/netshoot:latest
kind load docker-image nicolaka/netshoot:latest --name=saas-cluster
```
